บทที่ 1 จาก 15

การติดตั้งและเริ่มรันโปรเจกต์ (Setup and Run)

อ้างอิง GitHub: บรานช์ 01-setup

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนติดตั้ง Django เวอร์ชัน 4.0 ในสภาพแวดล้อมเสมือน (Virtual Environment) สร้างโปรเจกต์ (Project) ชื่อ project_jrd และเปิดเซิร์ฟเวอร์สำหรับพัฒนา (Development Server) เพื่อดูหน้าเว็บแรกในเบราว์เซอร์ (Browser) ได้

Django คือเฟรมเวิร์ก (Framework) สำหรับสร้างเว็บไซต์ด้วยภาษา Python โดยเฟรมเวิร์กคือชุดโครงสร้างและเครื่องมือสำเร็จรูปที่ช่วยให้ไม่ต้องเขียนทุกส่วนของเว็บไซต์เอง ในบทนี้คำสั่งทั้งหมดพิมพ์ใน เทอร์มินัล (Terminal) ได้แก่ Command Prompt หรือ PowerShell บน Windows และ Terminal บน macOS หรือ Linux

ขั้นตอนที่ 1 ตรวจสอบ Python

Python คือภาษาโปรแกรมที่ใช้เขียน Django จึงต้องติดตั้ง Python ก่อน หากยังไม่มี ให้ดาวน์โหลดจาก https://www.python.org/downloads/ โดยเลือก Python 3.10 ซึ่งเป็นเวอร์ชันที่ Django 4.0 รองรับ และบน Windows ให้เลือกช่อง Add python.exe to PATH ในหน้าแรกของตัวติดตั้งก่อนกดติดตั้ง จากนั้นเปิดเทอร์มินัลแล้วพิมพ์คำสั่งตรวจสอบเวอร์ชัน

โค้ด / คำสั่งคำอธิบาย
pythonเรียกใช้โปรแกรม Python
--versionตัวเลือก (Option) ที่สั่งให้แสดงเวอร์ชันแล้วจบการทำงาน

บน macOS และ Linux ให้ใช้ python3 --version และใช้ python3 แทน python และ pip3 แทน pip ในขั้นตอนที่ 2

ขั้นตอนที่ 2 ติดตั้ง pipenv

pip คือโปรแกรมติดตั้งแพ็กเกจ (Package) ของ Python โดยแพ็กเกจคือชุดโค้ดที่ผู้อื่นเขียนไว้ให้นำมาใช้ต่อ ส่วน pipenv คือเครื่องมือที่สร้างสภาพแวดล้อมเสมือนและจัดการแพ็กเกจของโปรเจกต์ สภาพแวดล้อมเสมือนคือพื้นที่แยกต่างหากสำหรับติดตั้งแพ็กเกจของแต่ละโปรเจกต์ ทำให้เวอร์ชันของแพ็กเกจในโปรเจกต์หนึ่งไม่กระทบอีกโปรเจกต์หนึ่ง

โค้ด / คำสั่งคำอธิบาย
pip installสั่งให้ pip ดาวน์โหลดและติดตั้งแพ็กเกจ
pipenvชื่อแพ็กเกจที่ต้องการติดตั้ง

ติดตั้งครั้งเดียวต่อเครื่อง ไม่ต้องทำซ้ำในแต่ละโปรเจกต์

ขั้นตอนที่ 3 สร้างโฟลเดอร์ของโปรเจกต์

โค้ด / คำสั่งคำอธิบาย
mkdir django-junraiderสร้างโฟลเดอร์ (Folder) ชื่อ django-junraider
cd django-junraiderเปลี่ยนตำแหน่งที่เทอร์มินัลทำงานอยู่ไปยังโฟลเดอร์นั้น คำสั่งในขั้นตอนต่อไปทั้งหมดต้องพิมพ์ในโฟลเดอร์นี้

ขั้นตอนที่ 4 ติดตั้ง Django

โค้ด / คำสั่งคำอธิบาย
pipenv installสั่งให้ pipenv ติดตั้งแพ็กเกจลงในสภาพแวดล้อมเสมือนของโฟลเดอร์นี้ ถ้ายังไม่มีสภาพแวดล้อมเสมือน pipenv จะสร้างให้เอง
djangoชื่อแพ็กเกจ Django
==4.0.*กำหนดเวอร์ชัน: ติดตั้งเวอร์ชัน 4.0 รุ่นล่าสุด (4.0.x) เพราะ Django รุ่นใหม่กว่ามีรายละเอียดบางส่วนต่างจาก 4.0 จึงต้องกำหนดเวอร์ชันให้ตรงกับที่บทเรียนนี้ใช้
" "เครื่องหมายคำพูดครอบข้อความ เพื่อไม่ให้เทอร์มินัลตีความเครื่องหมาย * เป็นอย่างอื่น

เมื่อติดตั้งเสร็จ จะมีไฟล์ใหม่ 2 ไฟล์ในโฟลเดอร์ คือ Pipfile และ Pipfile.lock

  • Pipfile เก็บรายชื่อแพ็กเกจที่โปรเจกต์ต้องใช้ พร้อมเงื่อนไขเวอร์ชัน
  • Pipfile.lock เก็บเวอร์ชันที่ติดตั้งจริงของทุกแพ็กเกจ รวมถึงแพ็กเกจที่ Django เรียกใช้ต่อ เพื่อให้เครื่องอื่นติดตั้งได้เวอร์ชันเดียวกัน

ขั้นตอนที่ 5 เข้าสู่สภาพแวดล้อมเสมือน

คำสั่งนี้เปิดเทอร์มินัลที่ทำงานภายในสภาพแวดล้อมเสมือน สังเกตได้จากชื่อโฟลเดอร์ในวงเล็บหน้าบรรทัดคำสั่ง เช่น (django-junraider) ต้องเข้าสู่สภาพแวดล้อมนี้ทุกครั้งที่เปิดเทอร์มินัลใหม่ก่อนทำงานกับโปรเจกต์ จากนั้นตรวจสอบว่า Django ติดตั้งแล้ว

โค้ด / คำสั่งคำอธิบาย
django-adminโปรแกรมคำสั่งของ Django ที่ได้มาพร้อมกับการติดตั้ง ใช้จัดการงานระดับโปรเจกต์ เช่น การสร้างโปรเจกต์
--versionแสดงเวอร์ชันของ Django

ขั้นตอนที่ 6 สร้างโปรเจกต์

โค้ด / คำสั่งคำอธิบาย
django-admin startprojectคำสั่งย่อย startproject สร้างโปรเจกต์ใหม่ ซึ่งคือโฟลเดอร์และไฟล์พื้นฐานที่ Django ต้องใช้
project_jrdชื่อโปรเจกต์ ใช้เป็นชื่อโฟลเดอร์ที่เก็บการตั้งค่า ชื่อต้องเป็นตัวอักษรภาษาอังกฤษ ตัวเลข หรือเครื่องหมาย _ และไม่ควรซ้ำกับชื่อของ Python หรือ Django เช่น django หรือ test
.จุดหมายถึงโฟลเดอร์ปัจจุบัน ทำให้ไฟล์ manage.py ถูกสร้างในโฟลเดอร์ django-junraider โดยตรง หากไม่ใส่จุด Django จะสร้างโฟลเดอร์ซ้อนเพิ่มอีกชั้น

เมื่อสำเร็จ จะไม่มีข้อความแสดงในเทอร์มินัล แต่จะมีไฟล์ใหม่ปรากฏในโฟลเดอร์ ดูโครงสร้างไฟล์ท้ายบทนี้

หน้าที่ของไฟล์ที่ Django สร้างให้

ไฟล์หน้าที่
manage.pyโปรแกรมคำสั่งประจำโปรเจกต์ ใช้สั่งงาน เช่น เปิดเซิร์ฟเวอร์ ในบทนี้ใช้ผ่านคำสั่ง python manage.py ...
project_jrd/__init__.pyไฟล์ว่างที่บอก Python ว่าโฟลเดอร์ project_jrd เป็นแพ็กเกจของ Python
project_jrd/settings.pyไฟล์การตั้งค่า (Settings) ของโปรเจกต์ทั้งหมด
project_jrd/urls.pyไฟล์ประกาศเส้นทาง (URL) ของเว็บไซต์ ใช้ในบทที่ 3
project_jrd/asgi.py และ project_jrd/wsgi.pyจุดเชื่อมต่อให้เว็บเซิร์ฟเวอร์ที่รองรับมาตรฐาน ASGI หรือ WSGI (มาตรฐานการเชื่อมต่อระหว่างเว็บเซิร์ฟเวอร์กับโปรแกรมที่เขียนด้วย Python) เรียกใช้โปรเจกต์ ใช้ตอนนำเว็บขึ้นใช้งานจริงในบทที่ 15

ขั้นตอนที่ 7 เปิดเซิร์ฟเวอร์สำหรับพัฒนา

โค้ด / คำสั่งคำอธิบาย
python manage.pyเรียก manage.py ด้วย Python เพื่อสั่งงานโปรเจกต์
runserverคำสั่งเปิดเซิร์ฟเวอร์สำหรับพัฒนา ซึ่งเป็นเว็บเซิร์ฟเวอร์ขนาดเล็กที่ Django มีให้ ใช้ทดลองในเครื่องของตนเองเท่านั้น ไม่ใช้เปิดให้ผู้ใช้จริง
  • ข้อความ You have 18 unapplied migration(s) เกี่ยวกับการสร้างตารางฐานข้อมูลของ Django ยังไม่ต้องดำเนินการในบทนี้ เนื้อหาเรื่องไมเกรชัน (Migration) อยู่ในบทที่ 7
  • http://127.0.0.1:8000/ คือที่อยู่ของเว็บไซต์ในเครื่องของผู้เรียน โดย 127.0.0.1 หมายถึงเครื่องของตนเอง และ 8000 คือหมายเลขพอร์ต (Port) ที่เซิร์ฟเวอร์รับคำขอ
  • เทอร์มินัลนี้ต้องเปิดไว้ตลอดขณะใช้งานเว็บ ถ้าต้องพิมพ์คำสั่งอื่นให้เปิดเทอร์มินัลใหม่และทำขั้นตอนที่ 5 อีกครั้ง

ขั้นตอนที่ 8 เปิดเว็บในเบราว์เซอร์และหยุดเซิร์ฟเวอร์

เปิดเบราว์เซอร์แล้วพิมพ์ที่อยู่ http://127.0.0.1:8000/ ในช่องที่อยู่ หน้าเว็บที่แสดงเป็นหน้าต้อนรับของ Django เมื่อต้องการหยุดเซิร์ฟเวอร์ ให้กดปุ่ม Ctrl และ C พร้อมกันในเทอร์มินัลที่รันเซิร์ฟเวอร์ (บน Windows อาจใช้ Ctrl และ Break)

ผลลัพธ์ที่ควรได้

  • เบราว์เซอร์แสดงหน้าที่มีข้อความ The install worked successfully! Congratulations! พร้อมภาพจรวด
  • มีไฟล์ db.sqlite3 เพิ่มในโฟลเดอร์ ซึ่งเป็นไฟล์ฐานข้อมูล SQLite (ระบบฐานข้อมูลที่เก็บข้อมูลทั้งหมดในไฟล์เดียว) ที่ Django สร้างขึ้นเมื่อเริ่มเซิร์ฟเวอร์ (ตั้งค่าไว้ใน DATABASES ของ settings.py) ยังไม่มีตารางใด
  • เทอร์มินัลแสดงบรรทัด GET / HTTP/1.1 ตามด้วยตัวเลข 200 เมื่อโหลดหน้าเว็บ ซึ่งหมายถึงเซิร์ฟเวอร์ตอบกลับสำเร็จ
