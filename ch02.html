บทที่ 2 จาก 15

โปรเจกต์และแอปพลิเคชัน (Projects x Apps)

อ้างอิง GitHub: บรานช์ 02-project-apps · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนอธิบายความต่างระหว่างโปรเจกต์ (Project) กับแอปพลิเคชัน (Application) ของ Django ได้ และสร้างแอปพลิเคชันชื่อ app_general และ app_foods ได้

ขั้นตอนที่ 1 ทำความเข้าใจโปรเจกต์และแอปพลิเคชัน

ตามเอกสารของ Django โปรเจกต์คือชุดของการตั้งค่าและแอปพลิเคชันสำหรับเว็บไซต์หนึ่งแห่ง ส่วนแอปพลิเคชัน (เรียกสั้นว่า แอป) คือส่วนของเว็บที่ทำหน้าที่เฉพาะอย่างหนึ่ง โปรเจกต์หนึ่งมีได้หลายแอป และแอปหนึ่งนำไปใช้ในหลายโปรเจกต์ได้

โปรเจกต์นี้แบ่งเป็น 2 แอป ดังนี้

แอปหน้าที่ในโปรเจกต์นี้
app_generalหน้าทั่วไปของเว็บ ได้แก่ หน้าแรกและหน้าเกี่ยวกับ
app_foodsหน้าที่เกี่ยวกับรายการอาหาร ได้แก่ หน้ารายการเมนูและหน้ารายละเอียดเมนู

ก่อนทำขั้นตอนถัดไป ให้เปิดเทอร์มินัลในโฟลเดอร์ django-junraider และเข้าสู่สภาพแวดล้อมเสมือนด้วย pipenv shell ตามขั้นตอนที่ 5 ของบทที่ 1 หากเซิร์ฟเวอร์จากบทที่ 1 ยังเปิดอยู่ ให้หยุดด้วย Ctrl และ C ก่อน

ขั้นตอนที่ 2 สร้างแอป app_general

โค้ด / คำสั่งคำอธิบาย
python manage.pyเรียก manage.py ด้วย Python เพื่อสั่งงานโปรเจกต์
startappคำสั่งย่อยสร้างแอปใหม่ ซึ่งคือโฟลเดอร์ที่มีไฟล์พื้นฐานของแอป
app_generalชื่อแอป ใช้เป็นชื่อโฟลเดอร์ของแอปด้วย

ขั้นตอนที่ 3 สร้างแอป app_foods

คำสั่งนี้ทำงานเหมือนขั้นตอนที่ 2 แต่ใช้ชื่อแอปเป็น app_foods

ขั้นตอนที่ 4 ตรวจสอบไฟล์ที่ Django สร้างให้

แต่ละแอปมีโฟลเดอร์ของตนเอง และมีไฟล์เหมือนกันดังตารางต่อไปนี้ ในบทนี้ยังไม่ต้องแก้ไขไฟล์ใด

ไฟล์ / โฟลเดอร์หน้าที่
__init__.pyไฟล์ว่างที่บอก Python ว่าโฟลเดอร์นี้เป็นแพ็กเกจของ Python
admin.pyใช้ลงทะเบียนโมเดลเพื่อแสดงในหน้าผู้ดูแลระบบ (Admin) ใช้ในบทที่ 11
apps.pyเก็บคลาส (Class) ที่ตั้งค่าของแอป
migrations/โฟลเดอร์เก็บไมเกรชัน (Migration) ซึ่งเป็นบันทึกการเปลี่ยนแปลงโครงสร้างฐานข้อมูล ใช้ในบทที่ 7
models.pyใช้ประกาศโมเดล (Model) ซึ่งกำหนดโครงสร้างข้อมูลที่เก็บในฐานข้อมูล ใช้ในบทที่ 7 และ 8
tests.pyใช้เขียนการทดสอบอัตโนมัติ (Test) ของแอป ไม่ได้ใช้ในชุดบทเรียนนี้
views.pyใช้เขียนวิว (View) ซึ่งเป็นฟังก์ชันที่รับคำขอของผู้ใช้และส่งผลลัพธ์กลับ ใช้ในบทที่ 3

ไฟล์ apps.py ของแต่ละแอปมีเนื้อหาดังนี้ ซึ่งเป็นโค้ดที่ Django สร้างให้ ไม่ต้องพิมพ์เอง

โค้ด / คำสั่งคำอธิบาย
from django.apps import AppConfigนำคลาส AppConfig จาก Django เข้ามาใช้
class AppGeneralConfig(AppConfig):สร้างคลาสการตั้งค่าของแอป โดยรับคุณสมบัติจาก AppConfig (ในไฟล์ของ app_foods ชื่อคลาสคือ AppFoodsConfig)
default_auto_field = 'django.db.models.BigAutoField'กำหนดชนิดของคอลัมน์ id ที่ Django สร้างให้อัตโนมัติในแต่ละโมเดลเป็นจำนวนเต็มขนาดใหญ่ (BigAutoField) รายละเอียดอยู่ในบทที่ 7
name = 'app_general'ชื่อแอป ต้องตรงกับชื่อโฟลเดอร์ของแอป

แอปที่สร้างแล้วยังไม่ถูกลงทะเบียนในโปรเจกต์ ผู้เรียนจะลงทะเบียนในบทที่ 4

ผลลัพธ์ที่ควรได้

  • คำสั่ง startapp ทั้งสองคำสั่งไม่แสดงข้อความใดในเทอร์มินัล
  • มีโฟลเดอร์ app_general และ app_foods ปรากฏข้าง manage.py โดยแต่ละโฟลเดอร์มีไฟล์ตามตารางในขั้นตอนที่ 4
