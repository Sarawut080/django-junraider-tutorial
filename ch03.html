เส้นทางและวิว (urls x views)

อ้างอิง GitHub: บรานช์ 03-urls-views · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนเขียนวิว (View) และกำหนดเส้นทาง (URL) เพื่อให้เบราว์เซอร์เปิด 4 ที่อยู่ของเว็บได้ ได้แก่ หน้าแรก หน้าเกี่ยวกับ หน้ารายการเมนู และหน้ารายละเอียดเมนูตามหมายเลข

ขั้นตอนที่ 1 ทำความเข้าใจการทำงานของ URL และวิว

เมื่อผู้ใช้พิมพ์ที่อยู่ในเบราว์เซอร์ เบราว์เซอร์ส่งคำขอ (Request) ไปยังเซิร์ฟเวอร์ Django จะนำส่วนท้ายของที่อยู่ (เช่น /about) ไปเทียบกับรายการเส้นทางที่ประกาศไว้ เมื่อพบเส้นทางที่ตรงกัน จะเรียกวิวที่ผูกกับเส้นทางนั้น วิวคือฟังก์ชัน Python ที่รับคำขอแล้วคืนการตอบกลับ (Response) ให้เบราว์เซอร์แสดงผล

ไฟล์ที่ประกาศรายการเส้นทางเรียกว่า URLconf ในบทนี้แต่ละแอปมีไฟล์ urls.py ของตนเอง และไฟล์ project_jrd/urls.py ของโปรเจกต์ทำหน้าที่รวมไฟล์เหล่านั้นเข้าด้วยกัน

ขั้นตอนที่ 2 เขียนวิวของ app_general

เปิดไฟล์ app_general/views.py ซึ่ง Django สร้างไว้แล้ว แทนที่เนื้อหาเดิมทั้งหมดด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
from django.http.response import HttpResponseนำคลาส HttpResponse เข้ามาใช้ คลาสนี้สร้างการตอบกลับที่มีข้อความตามที่กำหนด
from django.shortcuts import renderนำฟังก์ชัน render เข้ามา บรรทัดนี้ Django สร้างไว้ให้ ยังไม่ได้ใช้ในบทนี้ และจะใช้ในบทที่ 4
# Create your views here.คอมเมนต์ (Comment) ขึ้นต้นด้วย # Python ไม่นำไปทำงาน
def home(request):ประกาศฟังก์ชันวิวชื่อ home พารามิเตอร์ request คือคำขอที่ Django ส่งเข้ามา
return HttpResponse('<h1>จันทร์ไรเดอร์</h1>')ส่งการตอบกลับเป็นข้อความ HTML ซึ่งเป็นภาษาที่ใช้กำหนดส่วนประกอบของหน้าเว็บ (อธิบายเพิ่มในบทที่ 4) โดย <h1> คือแท็ก (Tag) หัวข้อใหญ่ของ HTML เบราว์เซอร์จะแสดงข้อความ จันทร์ไรเดอร์ เป็นหัวข้อขนาดใหญ่
def about(request):ประกาศฟังก์ชันวิวชื่อ about สำหรับหน้าเกี่ยวกับ
return HttpResponse('เกี่ยวกับจันทร์ไรเดอร์')ส่งการตอบกลับเป็นข้อความธรรมดา

ขั้นตอนที่ 3 สร้าง urls.py ของ app_general

Django ไม่สร้างไฟล์ urls.py ให้ในแอป ให้สร้างไฟล์ใหม่ชื่อ app_general/urls.py ในโฟลเดอร์ app_general แล้วพิมพ์โค้ดนี้

โค้ด / คำสั่งคำอธิบาย
from django.urls import pathนำฟังก์ชัน path ซึ่งใช้ประกาศหนึ่งเส้นทางเข้ามาใช้
from . import viewsนำไฟล์ views.py ในโฟลเดอร์เดียวกัน (แทนด้วยจุด) เข้ามาใช้ เพื่ออ้างถึงวิวที่เขียนไว้
urlpatterns = [ ... ]รายการเส้นทางของแอป Django ใช้ตัวแปรชื่อ urlpatterns นี้เท่านั้น จึงต้องตั้งชื่อตามนี้
path('', views.home, name='home')เส้นทางแรก: ข้อความว่าง '' หมายถึงที่อยู่หลักของแอป ให้เรียกวิว views.home และตั้งชื่อเส้นทางว่า home ชื่อนี้ใช้อ้างถึงเส้นทางในบทที่ 5
path('about', views.about, name='about')เส้นทางที่สอง: ที่อยู่ about เรียกวิว views.about และตั้งชื่อว่า about

path รับพารามิเตอร์ 3 ตัวตามลำดับ คือ รูปแบบเส้นทาง (Route) วิวที่จะเรียก และ name ชื่อของเส้นทาง

ขั้นตอนที่ 4 เขียนวิวของ app_foods

เปิดไฟล์ app_foods/views.py แล้วแทนที่เนื้อหาเดิมทั้งหมดด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
def foods(request):วิวสำหรับหน้ารายการเมนู ส่งข้อความธรรมดากลับ
def food(request, food_id):วิวสำหรับหน้ารายละเอียดเมนู มีพารามิเตอร์เพิ่ม food_id เพื่อรับหมายเลขเมนูจากเส้นทาง
str(food_id)แปลงจำนวนเต็ม food_id เป็นข้อความด้วยฟังก์ชัน str เพราะ Python ต่อข้อความกับจำนวนเต็มด้วยเครื่องหมาย + โดยตรงไม่ได้

สองบรรทัด import ด้านบนของไฟล์มีความหมายเหมือนไฟล์ app_general/views.py

ขั้นตอนที่ 5 สร้าง urls.py ของ app_foods

สร้างไฟล์ใหม่ชื่อ app_foods/urls.py แล้วพิมพ์โค้ดนี้

โค้ด / คำสั่งคำอธิบาย
path('', views.foods, name='foods')เส้นทางหลักของแอป เรียกวิว views.foods
path('<int:food_id>', views.food, name='food')เส้นทางที่มีส่วนแปรผัน ส่วน <int:food_id> รับค่าจากที่อยู่ โดย int คือพาธคอนเวอร์เตอร์ (Path Converter) ที่รับเฉพาะตัวเลขจำนวนเต็ม และ food_id คือชื่อพารามิเตอร์ที่ส่งให้วิว จึงต้องตรงกับพารามิเตอร์ของฟังก์ชัน food

ขั้นตอนที่ 6 รวมเส้นทางในไฟล์ urls.py ของโปรเจกต์

เปิดไฟล์ project_jrd/urls.py ส่วนบนของไฟล์เป็นข้อความอธิบายที่ Django สร้างให้ ไม่ต้องแก้ไข ให้แก้เฉพาะตั้งแต่บรรทัด from django.contrib import admin จนจบไฟล์ ให้เป็นดังนี้

โค้ด / คำสั่งคำอธิบาย
from django.urls import path, includeเพิ่มฟังก์ชัน include เข้ามา เดิมมีเฉพาะ path
path('', include('app_general.urls'))ส่งที่อยู่ไปให้ไฟล์ urls.py ของ app_general พิจารณาก่อน ถ้าไม่ตรงกับเส้นทางใดในไฟล์นั้น Django จะตรวจรายการถัดไป
path('foods/', include('app_foods.urls'))ที่อยู่ที่ขึ้นต้นด้วย foods/ ให้ตัดส่วน foods/ ออก แล้วส่งส่วนที่เหลือไปให้ urls.py ของ app_foods พิจารณา เช่น foods/1 จะเหลือ 1
path('admin/', admin.site.urls)เส้นทางของหน้าผู้ดูแลระบบที่ Django สร้างไว้ให้ ใช้ในบทที่ 11

Django ตรวจเส้นทางจากบนลงล่างและใช้เส้นทางแรกที่ตรงกัน

ขั้นตอนที่ 7 เปิดเซิร์ฟเวอร์และทดสอบ

เปิดเบราว์เซอร์แล้วทดสอบที่อยู่ต่อไปนี้ทีละที่อยู่

ผลลัพธ์ที่ควรได้

ที่อยู่ผลที่เห็น
http://127.0.0.1:8000/แสดงข้อความ จันทร์ไรเดอร์ เป็นหัวข้อขนาดใหญ่
http://127.0.0.1:8000/aboutแสดงข้อความ เกี่ยวกับจันทร์ไรเดอร์
http://127.0.0.1:8000/foods/แสดงข้อความ เมนูอร่อย ส่งบ่อย ส่งแม่น By Junraider
http://127.0.0.1:8000/foods/1แสดงข้อความ รายละเอียดของเมนูนี้ id = 1
http://127.0.0.1:8000/foods/12แสดงข้อความ รายละเอียดของเมนูนี้ id = 12 (ตัวเลขในที่อยู่ถูกส่งเข้าวิวเป็น food_id)
http://127.0.0.1:8000/foods/abcแสดงหน้า Page not found (404) เพราะ <int:food_id> รับเฉพาะตัวเลข
http://127.0.0.1:8000/about/แสดงหน้า Page not found (404) เพราะเส้นทางที่ประกาศคือ about ไม่มีเครื่องหมาย / ท้ายที่อยู่
