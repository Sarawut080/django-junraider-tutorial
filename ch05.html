บทที่ 5 จาก 15

แท็กในเทมเพลต (templates x tags)

อ้างอิง GitHub: บรานช์ 05-templates-tags · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนใช้แท็ก (Tag) ของเทมเพลต ได้แก่ extends, block, include, url, for, empty และ if และส่งข้อมูลจากวิวไปแสดงในเทมเพลตได้ ทำให้ส่วนหัวและส่วนท้ายของเว็บอยู่ในไฟล์เดียวและรายการเมนูแสดงจากข้อมูลในวิว

ขั้นตอนที่ 1 ทำความเข้าใจภาษาของเทมเพลต

เทมเพลตของ Django เป็นไฟล์ HTML ที่แทรกไวยากรณ์พิเศษได้ 2 แบบ ตามเอกสารของ Django

ไวยากรณ์ความหมาย
{{ ชื่อตัวแปร }}ตัวแปร (Variable) คือค่าที่ส่งมาจากวิว Django นำค่านั้นมาแสดงแทนที่ตรงตำแหน่งนี้
{% ชื่อแท็ก %}แท็ก (Tag) คือคำสั่งของเทมเพลต ใช้ควบคุมการทำงาน เช่น ทำซ้ำ ตรวจเงื่อนไข หรือนำเทมเพลตอื่นมาใช้ แท็กบางชนิดต้องมีแท็กปิด เช่น {% if %} ต้องปิดด้วย {% endif %}

ขั้นตอนที่ 2 สร้างเทมเพลตฐาน base.html

บทที่ 4 ทุกหน้ามีโครงเอกสาร ส่วนหัว และส่วนท้ายซ้ำกัน ขั้นตอนนี้แยกส่วนที่ซ้ำไว้ในไฟล์กลาง สร้างโฟลเดอร์ components ใน app_general/templates/app_general/ แล้วสร้างไฟล์ base.html ในโฟลเดอร์นั้น

โค้ด / คำสั่งคำอธิบาย
{% block site_title %}{% endblock %}ประกาศบล็อก (Block) ชื่อ site_title ซึ่งเป็นช่องว่างที่เทมเพลตอื่นเลือกเติมข้อความได้ ข้อความที่เติมจะอยู่หน้าคำว่า จันทร์ไรเดอร์ ในแท็ก <title>
{% include 'app_general/components/site_header.html' %}แท็ก include นำเนื้อหาของไฟล์เทมเพลตอื่นมาใส่ตรงตำแหน่งนี้ ในที่นี้คือส่วนหัวของเว็บ
{% block content %}{% endblock %}ประกาศบล็อกชื่อ content เป็นช่องสำหรับเนื้อหาหลักของแต่ละหน้า
{% include 'app_general/components/site_footer.html' %}นำส่วนท้ายของเว็บมาใส่ตรงตำแหน่งนี้

ขั้นตอนที่ 3 สร้างส่วนหัวและส่วนท้าย

สร้างไฟล์ 2 ไฟล์ในโฟลเดอร์ components เดียวกัน

โค้ด / คำสั่งคำอธิบาย
{% url 'home' %}แท็ก url สร้างที่อยู่ของเส้นทางที่ตั้งชื่อ (name) ว่า home ไว้ใน urls.py ของบทที่ 3 ผลลัพธ์คือ /
{% url 'foods' %}สร้างที่อยู่ของเส้นทางชื่อ foods ได้ /foods/
{% url 'about' %}สร้างที่อยู่ของเส้นทางชื่อ about ได้ /about

ข้อดีของแท็ก url คือหากแก้รูปแบบเส้นทางใน urls.py ที่อยู่ในลิงก์จะเปลี่ยนตามเอง โดยไม่ต้องแก้ทุกเทมเพลต ส่วนท้ายไม่มีแท็กของเทมเพลต เป็น HTML ล้วนที่ย้ายมาจาก home.html ของบทที่ 4

ขั้นตอนที่ 4 ให้หน้า home และ about ใช้เทมเพลตฐาน

แทนที่เนื้อหาของไฟล์ทั้งสองด้วยโค้ดต่อไปนี้

โค้ด / คำสั่งคำอธิบาย
{% extends 'app_general/components/base.html' %}แท็ก extends บอกว่าเทมเพลตนี้สืบทอดจากเทมเพลตฐาน ต้องเป็นแท็กแรกของไฟล์ เนื้อหานอกบล็อกจะไม่ถูกแสดง
{% block content %} ... {% endblock %}เนื้อหาระหว่างแท็กนี้ถูกนำไปใส่ในบล็อก content ของ base.html
{% block site_title %}เกี่ยวกับหมู่เฮา - {% endblock %}ใน about.html เติมข้อความในบล็อก site_title ทำให้ชื่อแท็บเป็น เกี่ยวกับหมู่เฮา - จันทร์ไรเดอร์ เมนูอร่อย ส่งบ่อย ส่งแม่น ส่วน home.html ไม่ได้เติม ชื่อแท็บจึงไม่มีข้อความนำหน้า

ขั้นตอนที่ 5 ส่งข้อมูลจากวิวไปยังเทมเพลต

แทนที่เนื้อหาของ app_foods/views.py ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
all_foods = [ {...}, {...}, {...} ]ตัวแปร all_foods เป็นลิสต์ (List) ซึ่งเก็บข้อมูลเรียงกัน แต่ละสมาชิกเป็นดิกชันนารี (Dictionary) ซึ่งเก็บข้อมูลเป็นคู่ คีย์ : ค่า เช่น 'title': 'Red Spicy' ข้อมูล 3 เมนูนี้แทนข้อมูลจริงชั่วคราว ก่อนใช้ฐานข้อมูลในบทที่ 7
'isPremium': Falseค่าบูลีน (Boolean) บอกว่าเป็นเมนูพิเศษหรือไม่ โดย True คือใช่ False คือไม่ใช่
context = {'foods': all_foods}คอนเท็กซ์ (Context) คือดิกชันนารีที่ส่งไปเทมเพลต คีย์ foods กลายเป็นชื่อตัวแปร foods ในเทมเพลต
render(request, 'app_foods/foods.html', context)พารามิเตอร์ตัวที่สามของ render คือคอนเท็กซ์
one_food = Noneกำหนดค่าเริ่มต้นเป็น None ซึ่งหมายถึงยังไม่มีค่า
[f for f in all_foods if f['id'] == food_id][0]สร้างลิสต์ใหม่ที่มีเฉพาะเมนูซึ่ง id ตรงกับ food_id จากที่อยู่ (รูปแบบนี้เรียกว่า List Comprehension) แล้วเลือกสมาชิกลำดับที่ 0 คือตัวแรก
try: ... except IndexError:ลองทำคำสั่งใน try ถ้าไม่พบเมนู ลิสต์จะว่าง และการเลือกลำดับที่ 0 จะเกิดข้อผิดพลาดชนิด IndexError โปรแกรมจึงเข้าไปทำงานใน except แทนที่จะหยุดทำงาน
print('ไม่มีเธอ ไม่เจอ Index')แสดงข้อความในเทอร์มินัลที่รันเซิร์ฟเวอร์ ไม่แสดงบนหน้าเว็บ
context = {'food': one_food}ส่งเมนูที่พบ (หรือ None ถ้าไม่พบ) ไปเทมเพลตในชื่อ food

ไฟล์ app_general/views.py ไม่ต้องแก้ไข

ขั้นตอนที่ 6 แสดงรายการเมนูด้วย for, if และ empty

แทนที่เนื้อหาของ foods.html ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
{% for food in foods %} ... {% empty %} ... {% endfor %}แท็ก for วนซ้ำ (Loop) ทีละสมาชิกของ foods ที่วิวส่งมา โดยในแต่ละรอบตัวแปร food คือเมนูหนึ่งรายการ ส่วนระหว่าง {% empty %} กับ {% endfor %} จะแสดงเมื่อ foods ไม่มีสมาชิก
{{ food.title }}ตัวแปรที่ใช้เครื่องหมายจุดดึงค่าของคีย์ title ในดิกชันนารี
{% url 'food' food.id %}แท็ก url กับเส้นทางชื่อ food ซึ่งต้องการค่า food_id จึงส่ง food.id ตามหลังชื่อ ได้ที่อยู่ เช่น /foods/1
{% if food.isPremium %} ... {% endif %}แสดงข้อความ *** เมนูพิเศษสุด Premium เมื่อค่าเป็นจริง (True)
{{ food.price }}แสดงราคา

ขั้นตอนที่ 7 แสดงรายละเอียดเมนู

แทนที่เนื้อหาของ food.html ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
{% block site_title %}{{ food.title }} - {% endblock %}ใส่ชื่อเมนูหน้าชื่อแท็บของเบราว์เซอร์
{% if food is not None %} ... {% else %} ... {% endif %}ถ้า food มีค่า (ไม่ใช่ None) ให้แสดงรายละเอียด ถ้าไม่ใช่ให้แสดง ไม่พบเมนู จึงใช้แท็ก else แสดงข้อความทางเลือก

ขั้นตอนที่ 8 เปิดเซิร์ฟเวอร์และทดสอบ

ผลลัพธ์ที่ควรได้

ที่อยู่ผลที่เห็น
http://127.0.0.1:8000/ และ /aboutทุกหน้ามีแถบสีเทาด้านบนและด้านล่างเหมือนกัน หน้า about มีแถบสีเทาแล้ว ซึ่งบทที่ 4 ไม่มี ชื่อแท็บของหน้า about ขึ้นต้นด้วย เกี่ยวกับหมู่เฮา -
http://127.0.0.1:8000/foods/แสดงเมนู 3 รายการ ได้แก่ Red Spicy 299, Blue Iceberg 299 และ Premium Black Choco 399 โดยเฉพาะรายการสุดท้ายมีข้อความ *** เมนูพิเศษสุด Premium และแต่ละชื่อเป็นลิงก์
http://127.0.0.1:8000/foods/3แสดงชื่อ Premium Black Choco ข้อความ *** เมนูพิเศษสุด Premium ราคา 399 และ อร่อยจนต้องต่อยรังแตน ชื่อแท็บเป็น Premium Black Choco - จันทร์ไรเดอร์ เมนูอร่อย ส่งบ่อย ส่งแม่น
http://127.0.0.1:8000/foods/1แสดงชื่อ Red Spicy ราคา 299 ไม่มีข้อความเมนูพิเศษ
http://127.0.0.1:8000/foods/99แสดงข้อความ ไม่พบเมนู และเทอร์มินัลที่รันเซิร์ฟเวอร์แสดง ไม่มีเธอ ไม่เจอ Index
