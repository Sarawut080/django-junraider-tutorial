บทที่ 7 จาก 15

โมเดลและไมเกรชัน (models x migrations)

อ้างอิง GitHub: บรานช์ 07-models-migrations · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนเชื่อมต่อโปรเจกต์กับฐานข้อมูล PostgreSQL ผ่านโปรแกรม pgAdmin ประกาศโมเดล (Model) ของเมนูอาหาร (Food) และผู้ลงทะเบียนรับโปรโมชั่น (Subscription) และสร้างตารางในฐานข้อมูลด้วยไมเกรชัน (Migration) ได้

ขั้นตอนที่ 1 ทำความเข้าใจโมเดลและไมเกรชัน

  • ฐานข้อมูล (Database) คือที่เก็บข้อมูลของเว็บอย่างเป็นระบบในรูปของตาราง (Table) ที่มีแถว (Row) และคอลัมน์ (Column) ตั้งแต่บทนี้ โปรเจกต์ใช้ PostgreSQL เป็นระบบจัดการฐานข้อมูล และใช้ pgAdmin ซึ่งเป็นโปรแกรมหน้าต่างสำหรับสร้างและดูฐานข้อมูล
  • โมเดล (Model) คือคลาส Python ที่ระบุโครงสร้างข้อมูลหนึ่งชนิด Django แปลงโมเดลหนึ่งคลาสเป็นตารางหนึ่งตาราง และแปลงฟิลด์ (Field) แต่ละตัวเป็นคอลัมน์
  • ไมเกรชัน (Migration) คือไฟล์ที่ Django สร้างขึ้นเพื่อบันทึกการเปลี่ยนแปลงของโมเดล และใช้สั่งให้ฐานข้อมูลเปลี่ยนโครงสร้างตาม ทำให้ไม่ต้องเขียนคำสั่ง SQL (ภาษาที่ใช้สั่งงานฐานข้อมูล) สร้างตารางเอง

ขั้นตอนที่ 2 ติดตั้ง PostgreSQL และ pgAdmin

ดาวน์โหลดตัวติดตั้ง PostgreSQL สำหรับ Windows จาก https://www.postgresql.org/download/windows/ ตัวติดตั้งมีให้เลือกติดตั้ง PostgreSQL Server และ pgAdmin 4 พร้อมกัน ระหว่างติดตั้งจะให้ตั้งรหัสผ่านของผู้ใช้ postgres ซึ่งเป็นผู้ดูแลระบบของ PostgreSQL และกำหนดพอร์ต (Port) ให้ใช้ค่าเริ่มต้น 5432 ให้จดรหัสผ่านไว้

ขั้นตอนที่ 3 สร้างฐานข้อมูลด้วย pgAdmin

  • เปิดโปรแกรม pgAdmin 4 (หากมีการให้ตั้ง Master Password ในการเปิดครั้งแรก ให้ตั้งรหัสผ่านสำหรับ pgAdmin เอง)
  • ในแผงด้านซ้าย ขยาย Servers แล้วคลิกเซิร์ฟเวอร์ที่ติดตั้งไว้ (ชื่อ PostgreSQL ตามด้วยเลขเวอร์ชัน เช่น PostgreSQL 17) กรอกรหัสผ่านของผู้ใช้ postgres ที่ตั้งตอนติดตั้ง
  • คลิกขวาที่ Databases เลือก Create แล้วเลือก Database…
  • ในช่อง Database พิมพ์ django_junraider แล้วกด Save
  • ฐานข้อมูล django_junraider จะปรากฏใต้ Databases

ชื่อ django_junraider ต้องตรงกับค่า NAME ที่ตั้งใน settings.py ในขั้นตอนที่ 5

ขั้นตอนที่ 4 ติดตั้งตัวเชื่อมต่อ PostgreSQL สำหรับ Python

Django ต้องใช้แพ็กเกจเชื่อมต่อกับ PostgreSQL (เรียกว่า Driver) ให้กลับไปที่เทอร์มินัลในสภาพแวดล้อมเสมือนของโปรเจกต์ (โฟลเดอร์ django-junraider ที่ทำ pipenv shell แล้ว) แล้วติดตั้ง

psycopg2 คือตัวเชื่อมต่อ PostgreSQL ที่ Django ใช้ ส่วนชื่อที่ลงท้ายด้วย -binary คือรุ่นที่สร้างสำเร็จรูปมาแล้ว จึงไม่ต้องติดตั้งตัวแปลภาษา C เพิ่ม

ขั้นตอนที่ 5 ตั้งค่าฐานข้อมูลใน settings.py

เปิดไฟล์ project_jrd/settings.py หา DATABASES ซึ่งเดิมใช้ SQLite (ฐานข้อมูลแบบไฟล์ที่ Django ตั้งให้) แล้วแทนที่ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
'ENGINE': 'django.db.backends.postgresql'ตัวเชื่อมต่อฐานข้อมูลที่ Django มีให้สำหรับ PostgreSQL (ใช้ psycopg2 ที่ติดตั้งในขั้นตอนที่ 4)
'NAME': 'django_junraider'ชื่อฐานข้อมูลที่สร้างในขั้นตอนที่ 3
'USER': 'postgres'ชื่อผู้ใช้ PostgreSQL
'PASSWORD': 'password1234'รหัสผ่านของผู้ใช้ ให้เปลี่ยนเป็นรหัสผ่านที่ตั้งไว้ตอนติดตั้ง PostgreSQL ของตนเอง
'HOST': '127.0.0.1'ที่อยู่ของเครื่องที่รัน PostgreSQL ในที่นี้คือเครื่องของตนเอง
'PORT': '5432'หมายเลขพอร์ตของ PostgreSQL ที่กำหนดตอนติดตั้ง

การเขียนรหัสผ่านในไฟล์โค้ดไม่ปลอดภัย บทที่ 14 จะย้ายค่าเหล่านี้ไปไว้ในไฟล์ .env

ขั้นตอนที่ 6 ประกาศโมเดล Food

แทนที่เนื้อหาทั้งไฟล์ app_foods/models.py ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
class Food(models.Model):ประกาศโมเดลชื่อ Food โดยรับคุณสมบัติจาก models.Model ของ Django ตารางที่ได้ชื่อ app_foods_food (ชื่อแอป + ชื่อโมเดลตัวพิมพ์เล็ก)
title = models.CharField(max_length=60)ฟิลด์ข้อความสั้น max_length คือจำนวนตัวอักษรสูงสุด
price = models.IntegerField()ฟิลด์จำนวนเต็ม
special_price = models.IntegerField(null=True)จำนวนเต็มที่ null=True อนุญาตให้ไม่มีค่า (เก็บเป็น NULL ในฐานข้อมูล) เหมาะกับเมนูที่ไม่มีราคาพิเศษ
is_premium = models.BooleanField(default=False)ฟิลด์บูลีน default=False คือค่าเริ่มต้นเมื่อไม่ระบุ
promotion_end_at = models.DateTimeField(null=True)ฟิลด์วันที่และเวลา อนุญาตให้ไม่มีค่า
description = models.TextField(null=True)ฟิลด์ข้อความยาว อนุญาตให้ไม่มีค่า

Django เพิ่มคอลัมน์ id ให้เองในทุกโมเดล เป็นจำนวนเต็มที่เพิ่มค่าอัตโนมัติและเป็นคีย์หลัก (Primary Key) ซึ่งใช้ระบุแถวแต่ละแถวไม่ให้ซ้ำกัน ชนิดของคอลัมน์นี้ตามค่า default_auto_field ใน apps.py ที่เห็นในบทที่ 2

ขั้นตอนที่ 7 ประกาศโมเดล Subscription

แทนที่เนื้อหาทั้งไฟล์ app_general/models.py ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
STATUS = [ ('unapproved', 'Unapproved'), ... ]รายการตัวเลือกของสถานะ แต่ละตัวเลือกเป็นคู่ (ค่าที่เก็บในฐานข้อมูล, ข้อความที่แสดงให้ผู้ใช้เห็น)
email = models.EmailField(max_length=50, unique=True)ฟิลด์อีเมล ตรวจรูปแบบอีเมล และ unique=True ห้ามมีอีเมลซ้ำกันในตาราง
status = models.CharField(max_length=15, choices=STATUS, default='unapproved')ฟิลด์ข้อความที่เลือกได้เฉพาะค่าใน STATUS ค่าเริ่มต้นคือ unapproved
registered_at = models.DateTimeField(auto_now_add=True)ฟิลด์วันที่และเวลาที่ Django ใส่เวลาปัจจุบันให้อัตโนมัติเมื่อสร้างแถวใหม่

ขั้นตอนที่ 8 สร้างไฟล์ไมเกรชัน

ผลลัพธ์ตัวอย่างมาจาก Windows บน macOS และ Linux เส้นทางไฟล์ใช้เครื่องหมาย / แทน \

คำสั่ง makemigrations เปรียบเทียบโมเดลปัจจุบันกับไมเกรชันเดิม แล้วสร้างไฟล์ไมเกรชันใหม่ในโฟลเดอร์ migrations ของแต่ละแอป ตัวอย่างไฟล์ app_foods/migrations/0001_initial.py ที่ได้

ไฟล์นี้ Django สร้างให้ ไม่ต้องแก้ไข บรรทัดแรกบอกเวอร์ชัน Django และเวลาที่สร้าง ซึ่งของผู้เรียนจะต่างจากตัวอย่าง CreateModel คือการสร้างตารางของโมเดล Food และ fields คือรายการคอลัมน์ ซึ่งมี id ที่ Django เพิ่มให้

ขั้นตอนที่ 9 สั่งให้ฐานข้อมูลเปลี่ยนตามไมเกรชัน

คำสั่ง migrate นำไมเกรชันที่ยังไม่ได้ใช้ทั้งหมดไปสร้างตารางในฐานข้อมูล รวมถึงไมเกรชันของแอปที่มากับ Django (admin, auth, contenttypes, sessions) ซึ่งเป็นสาเหตุของข้อความ 18 unapplied migration(s) ที่เห็นตอน runserver ในบทที่ 1 จำนวนและลำดับบรรทัดอาจต่างจากตัวอย่างเล็กน้อย

ขั้นตอนที่ 10 ตรวจสอบตารางใน pgAdmin

  • ใน pgAdmin ขยาย Servers > PostgreSQL (เลขเวอร์ชัน) > Databases > django_junraider > Schemas > public > Tables (ถ้าไม่เห็นตาราง ให้คลิกขวาที่ Tables แล้วเลือก Refresh)
  • ตาราง app_foods_food และ app_general_subscription ปรากฏในรายการ
  • คลิกขวาที่ตาราง app_foods_food เลือก Properties แล้วเปิดแท็บ Columns เพื่อดูคอลัมน์ หรือเลือก View/Edit Data > All Rows เพื่อดูข้อมูลในตาราง (ตอนนี้ยังไม่มีข้อมูล)

ผลลัพธ์ที่ควรได้

  • ใน pgAdmin ฐานข้อมูล django_junraider มีตาราง app_foods_food และ app_general_subscription รวมกับตารางของ Django เช่น auth_user และ django_session รวม 12 ตาราง
  • ตาราง app_foods_food มีคอลัมน์ id, title, price, special_price, is_premium, promotion_end_at, description โดยคอลัมน์ special_price, promotion_end_at, description อนุญาตให้ไม่มีค่า
  • ครั้งต่อไปที่รัน python manage.py runserver จะไม่มีข้อความเตือน unapplied migration(s) อีก
