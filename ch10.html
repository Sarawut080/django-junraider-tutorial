แบบฟอร์ม วิว และเทมเพลต (forms)

อ้างอิง GitHub: บรานช์ 10-forms-views-templates · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนสร้างแบบฟอร์ม (Form) ด้วยคลาสของ Django รับข้อมูลที่ผู้ใช้ส่งมา (POST) ตรวจสอบความถูกต้อง และบันทึกลงฐานข้อมูล ทำให้หน้าลงทะเบียนรับโปรโมชั่นใช้งานได้จริง

ขั้นตอนที่ 1 ทำความเข้าใจการทำงานของแบบฟอร์ม

  • เบราว์เซอร์ขอหน้าฟอร์มด้วยเมธอด (Method) GET แล้วผู้ใช้กรอกข้อมูลและกดส่ง เบราว์เซอร์จะส่งข้อมูลกลับมาด้วยเมธอด POST ไปยังที่อยู่เดียวกัน
  • วิวจึงต้องแยกการทำงานเป็น 2 กรณีตาม request.method คือ GET แสดงฟอร์มเปล่า และ POST รับข้อมูล ตรวจสอบ แล้วบันทึกหรือแสดงฟอร์มพร้อมข้อความผิดพลาด
  • คลาสฟอร์มของ Django (forms.Form) กำหนดฟิลด์และกติกาการตรวจสอบ ส่วน forms.ModelForm สร้างฟิลด์จากโมเดลให้อัตโนมัติและบันทึกลงฐานข้อมูลได้ด้วย save()
  • เมื่อบันทึกสำเร็จ วิวส่งผู้ใช้ไปหน้าอื่นด้วยการเปลี่ยนเส้นทาง (Redirect) เพื่อไม่ให้ส่งข้อมูลซ้ำเมื่อรีเฟรชหน้า

class FoodMultipleChoiceField(forms.ModelMultipleChoiceField):คลาสฟิลด์เลือกได้หลายรายการจากโมเดล ที่เขียนขึ้นเองโดยสืบทอดจากคลาสของ Django
def label_from_instance(self, obj): return obj.titleกำหนดข้อความที่แสดงเป็นตัวเลือกแต่ละรายการให้เป็นชื่อเมนู (title) แทนค่าเริ่มต้น
class SubscriptionForm(forms.Form):ฟอร์มแบบทั่วไป ประกาศฟิลด์ทีละตัวเอง ไม่ผูกกับโมเดล เขียนไว้เพื่อเปรียบเทียบกับ SubscriptionModelForm ด้านล่าง วิวในบทนี้ไม่ได้ใช้คลาสนี้
forms.CharField(max_length=50, required=True, label='ชื่อ-นามสกุล')ฟิลด์ข้อความ required=True คือห้ามเว้นว่าง และ label คือป้ายข้อความ
forms.EmailField(...)ฟิลด์อีเมล ตรวจรูปแบบอีเมล
queryset=Food.objects.order_by('-is_premium')ที่มาของตัวเลือก คือ QuerySet ของเมนู
widget=forms.CheckboxSelectMultipleวิดเจ็ต (Widget) คือส่วนที่กำหนดว่าฟิลด์แสดงเป็น HTML แบบใด ในที่นี้เป็นเช็กบอกซ์หลายช่อง
accepted = forms.BooleanField(required=True, ...)เช็กบอกซ์ยอมรับข้อตกลง ต้องเลือกจึงจะส่งได้ ฟิลด์นี้ไม่มีในโมเดล จึงไม่ถูกบันทึกลงฐานข้อมูล
class SubscriptionModelForm(forms.ModelForm):ฟอร์มที่ผูกกับโมเดล ฟิลด์ที่ไม่ได้ประกาศเองจะสร้างจากโมเดล
class Meta: model = Subscriptionคลาสย่อย Meta บอกรายละเอียดของฟอร์ม model คือโมเดลที่ผูก
fields = ['name', 'email', 'food_set', 'accepted']รายการฟิลด์ที่แสดงในฟอร์มตามลำดับ
labels = { ... }กำหนดป้ายข้อความของฟิลด์ที่สร้างจากโมเดล

แทนที่เนื้อหาของ app_general/views.py ด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
from django.http.response import HttpResponseRedirectคลาสที่สร้างการตอบกลับแบบเปลี่ยนเส้นทาง
from django.urls import reverseฟังก์ชัน reverse แปลงชื่อเส้นทางเป็นที่อยู่ในวิว เหมือนแท็ก url ในเทมเพลต
if request.method == 'POST':กรณีที่เบราว์เซอร์ส่งข้อมูลมา
form = SubscriptionModelForm(request.POST)สร้างฟอร์มที่มีข้อมูลที่ส่งมา (request.POST)
if form.is_valid():ตรวจสอบข้อมูลตามกติกาของฟิลด์ทั้งหมด ได้ True เมื่อถูกต้อง
form.save()บันทึกลงฐานข้อมูล รวมถึงเมนูที่เลือก (ความสัมพันธ์ food_set)
return HttpResponseRedirect(reverse('subscription_thankyou'))ส่งผู้ใช้ไปหน้าขอบคุณ
else: form = SubscriptionModelForm()กรณี GET สร้างฟอร์มเปล่า
context = {'form': form}ส่งฟอร์มไปเทมเพลต กรณี POST ที่ข้อมูลไม่ถูกต้อง โค้ดจะมาถึงบรรทัดนี้พร้อมฟอร์มที่เก็บข้อความผิดพลาดไว้ เพื่อแสดงให้ผู้ใช้แก้ไข

<form action="{% url 'subscription' %}" method="POST">ฟอร์ม HTML ส่งข้อมูลไปยังที่อยู่ของเส้นทาง subscription ด้วยเมธอด POST
{% csrf_token %}แท็กสร้างฮิดเดนฟิลด์ (Hidden Field) ที่เก็บโทเคนป้องกันการโจมตีแบบ CSRF (Cross-Site Request Forgery) ซึ่งคือการหลอกให้เบราว์เซอร์ของผู้ใช้ส่งคำขอไปยังเว็บโดยไม่รู้ตัว Django ปฏิเสธคำขอ POST ที่ไม่มีโทเคนนี้ ฟอร์ม POST ทุกฟอร์มต้องมีแท็กนี้
{{ form.non_field_errors }}ข้อความผิดพลาดที่ไม่เกี่ยวกับฟิลด์ใดฟิลด์หนึ่ง
{{ form.name.label_tag }}สร้างป้ายข้อความ (<label>) ของฟิลด์ name
{{ form.name }}สร้างช่องกรอกของฟิลด์ name ตามที่ประกาศในฟอร์ม
{{ form.name.errors }}แสดงข้อความผิดพลาดของฟิลด์นั้น เช่น ฟิลด์นี้จำเป็น หรือป้อนที่อยู่อีเมลที่ถูกต้อง
{{ form.accepted.label }}ข้อความป้ายของฟิลด์ที่แสดงเอง
<button type="submit">ปุ่มส่งฟอร์ม

ผลลัพธ์ที่ควรได้

การทดสอบผลที่เห็น
เปิดหน้าฟอร์มเห็นช่อง ชื่อ-นามสกุล อีเมล เช็กบอกซ์เมนู 5 รายการ (เมนูพิเศษอยู่ก่อน) และเช็กบอกซ์ยอมรับข้อตกลง
กดส่งโดยไม่กรอกข้อมูลเบราว์เซอร์แสดงข้อความเตือนที่ช่องแรกที่ยังไม่กรอก เพราะช่องกรอกมีคุณสมบัติ required ที่ Django ใส่ให้จาก required=True
กรอกอีเมลผิดรูปแบบ เช่น not-an-emailเบราว์เซอร์หรือ Django แสดงข้อความ ป้อนที่อยู่อีเมลที่ถูกต้อง
กรอกครบ เลือกเมนูอย่างน้อย 1 รายการ และเลือกช่องยอมรับข้อตกลง แล้วส่งเปลี่ยนไปหน้า /subscription/thankyou และมีแถวใหม่ในตาราง app_general_subscription (สถานะ unapproved) กับตาราง app_general_subscription_food_set ตามจำนวนเมนูที่เลือก ตรวจได้ใน pgAdmin ด้วย View/Edit Data > All Rows
กรอกชื่อ อีเมล เลือกช่องยอมรับข้อตกลง แต่ไม่เลือกเมนู แล้วส่งอยู่หน้าเดิม และแสดงข้อความ ฟิลด์นี้จำเป็น ใต้รายการเมนู ข้อความนี้มาจากการตรวจสอบของ Django (form.is_valid()) เพราะ food_set กำหนด required=True
ส่งอีเมลเดิมซ้ำไม่บันทึกซ้ำ และแสดงข้อความ Subscription และ Email มีอยู่แล้ว เพราะฟิลด์ email กำหนด unique=True
