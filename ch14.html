บทที่ 14 จาก 15

การตั้งค่าและไฟล์ .env (settings x dotenv)

อ้างอิง GitHub: บรานช์ 14-settings-dotenv · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนย้ายค่าการตั้งค่าที่เป็นความลับและค่าที่ต่างกันตามเครื่อง ได้แก่ รหัสลับของ Django การเปิดโหมดแก้จุดบกพร่อง และข้อมูลเชื่อมต่อฐานข้อมูล ออกจากไฟล์ settings.py ไปไว้ในไฟล์ .env และอ่านค่าเหล่านั้นด้วย python-dotenv ได้

ขั้นตอนที่ 1 ทำความเข้าใจตัวแปรสภาพแวดล้อมและไฟล์ .env

  • ตัวแปรสภาพแวดล้อม (Environment Variable) คือค่าที่ระบบปฏิบัติการเก็บไว้ให้โปรแกรมอ่านได้ โดยแต่ละค่ามีชื่อและข้อความที่เป็นค่า Python อ่านได้ด้วย os.getenv('ชื่อ') ซึ่งคืนค่า None ถ้าไม่มีชื่อนั้น หรือคืนค่าที่กำหนดเป็นพารามิเตอร์ตัวที่สองถ้าไม่มี
  • ไฟล์ .env คือไฟล์ข้อความที่เขียนค่าในรูป ชื่อ=ค่า บรรทัดละค่า แพ็กเกจ python-dotenv ช่วยอ่านไฟล์นี้แล้วตั้งเป็นตัวแปรสภาพแวดล้อมของโปรแกรม
  • เหตุผลที่แยกค่าออกจากโค้ด คือรหัสลับและรหัสผ่านไม่ควรอยู่ในโค้ดที่แชร์หรืออัปโหลดขึ้น GitHub และแต่ละเครื่อง (เครื่องของผู้เรียนกับเซิร์ฟเวอร์จริงในบทที่ 15) ต้องใช้ค่าต่างกัน เปลี่ยนค่าได้โดยไม่ต้องแก้โค้ด
  • ไฟล์ .env ต้องไม่ถูกอัปโหลดขึ้น GitHub ขั้นตอนที่ 5 สร้างไฟล์ .gitignore เพื่อกันไฟล์นี้ไว้

ขั้นตอนที่ 2 ติดตั้ง python-dotenv

ขั้นตอนที่ 3 สร้างไฟล์ .env

สร้างรหัสลับใหม่สำหรับโปรเจกต์ด้วยฟังก์ชันของ Django

คำสั่งนี้พิมพ์ข้อความสุ่มยาว 50 ตัวอักษร ให้คัดลอกไว้ใช้ในไฟล์ถัดไป จากนั้นสร้างไฟล์ชื่อ .env (ขึ้นต้นด้วยจุด ไม่มีชื่อก่อนจุด) ในโฟลเดอร์ project_jrd ข้างไฟล์ settings.py แล้วพิมพ์ค่าต่อไปนี้ โดยแทนที่ข้อความภายในเครื่องหมาย < > ด้วยค่าของผู้เรียนเอง

โค้ด / คำสั่งคำอธิบาย
DEBUG=Trueเปิดโหมดแก้จุดบกพร่อง (Debug Mode) ของ Django ซึ่งแสดงหน้าข้อผิดพลาดแบบละเอียด ใช้เฉพาะตอนพัฒนา
SECRET_KEY='...'รหัสลับที่ Django ใช้ลงลายเซ็นข้อมูล เช่น เซสชัน ต้องเก็บเป็นความลับ ครอบด้วยเครื่องหมายคำพูดเดี่ยวเพราะรหัสที่สุ่มมีเครื่องหมายพิเศษ เช่น # และ $
DB_NAME, DB_USER, DB_PASS, DB_HOST, DB_PORTข้อมูลเชื่อมต่อฐานข้อมูลที่เขียนไว้ใน settings.py ตั้งแต่บทที่ 7 ได้แก่ ชื่อฐานข้อมูล ชื่อผู้ใช้ รหัสผ่าน ที่อยู่เครื่อง และพอร์ต

ขั้นตอนที่ 4 สร้างไฟล์ .env.sample

ไฟล์ .env จะไม่ถูกอัปโหลดขึ้น GitHub ผู้ที่นำโปรเจกต์ไปใช้จึงไม่รู้ว่าต้องตั้งค่าอะไรบ้าง จึงควรมีไฟล์ตัวอย่างที่มีเฉพาะชื่อตัวแปรและค่าตัวอย่าง สร้างไฟล์ project_jrd/.env.sample

ผู้ที่ดาวน์โหลดโปรเจกต์ไปใช้ ให้คัดลอกไฟล์นี้เป็น .env แล้วแก้ค่าให้ตรงกับเครื่องของตน

ขั้นตอนที่ 5 สร้างไฟล์ .gitignore

ไฟล์ .gitignore คือรายชื่อไฟล์และโฟลเดอร์ที่โปรแกรม Git (โปรแกรมบันทึกประวัติการแก้ไขโค้ดและส่งโค้ดขึ้น GitHub) ไม่นำไปบันทึกและไม่อัปโหลดขึ้น GitHub (ใช้ในบทที่ 15) สร้างไฟล์ชื่อ .gitignore ในโฟลเดอร์ django-junraider (ข้าง manage.py) แล้วพิมพ์รายการนี้

รายการเหตุผล
__pycache__/ และ *.pycโฟลเดอร์และไฟล์ที่ Python สร้างเองขณะรันโปรแกรม ไม่ต้องเก็บ
db.sqlite3ไฟล์ฐานข้อมูล SQLite ที่ Django สร้างขึ้นเมื่อรัน runserver ในบทที่ 1 (ก่อนเปลี่ยนเป็น PostgreSQL ในบทที่ 7)
.envไฟล์ค่าลับของบทนี้ ต้องไม่อัปโหลด
.venv/โฟลเดอร์สภาพแวดล้อมเสมือน ถ้า pipenv สร้างไว้ในโฟลเดอร์โปรเจกต์

ขั้นตอนที่ 6 แก้ settings.py ให้อ่านค่าจาก .env

เปิดไฟล์ project_jrd/settings.py แล้วแก้ 3 ส่วน ส่วนแรกคือบรรทัด import ด้านบน เพิ่ม 3 รายการต่อจาก from pathlib import Path

โค้ด / คำสั่งคำอธิบาย
from dotenv import load_dotenvนำฟังก์ชัน load_dotenv ของ python-dotenv เข้ามา
import osนำโมดูล os ของ Python ซึ่งมี os.getenv เข้ามา
load_dotenv()ค้นหาไฟล์ .env ในโฟลเดอร์เดียวกับไฟล์นี้ (และโฟลเดอร์ที่อยู่เหนือขึ้นไป) แล้วโหลดค่าเป็นตัวแปรสภาพแวดล้อม ต้องเรียกก่อนบรรทัดที่ใช้ os.getenv

ส่วนที่สองคือ SECRET_KEY, DEBUG และ ALLOWED_HOSTS แทนที่บรรทัดเดิมด้วยโค้ดนี้

โค้ด / คำสั่งคำอธิบาย
SECRET_KEY = os.getenv('SECRET_KEY')อ่านรหัสลับจาก .env แทนข้อความที่ Django สร้างไว้ในไฟล์ (ขึ้นต้นด้วย django-insecure-)
DEBUG = os.getenv('DEBUG') == 'True'ตัวแปรสภาพแวดล้อมเป็นข้อความเสมอ จึงเทียบกับข้อความ 'True' ได้ผลเป็นค่าบูลีน ถ้าไม่มีตัวแปรนี้หรือมีค่าอื่น DEBUG จะเป็น False ซึ่งเป็นค่าที่ปลอดภัยกว่า
production_host = os.getenv('PRODUCTION_HOST')อ่านชื่อโดเมน (Domain) ของเว็บบนเซิร์ฟเวอร์จริง โดเมนคือชื่อที่ใช้เรียกเว็บไซต์ เช่น django-junraider.onrender.com ตัวแปรนี้ไม่ต้องใส่ใน .env ของเครื่องตนเอง จะใช้ในบทที่ 15
ALLOWED_HOSTS = [production_host] if ... else []ALLOWED_HOSTS คือรายชื่อโฮสต์ที่ Django ยอมรับคำขอ ถ้ามี PRODUCTION_HOST ใช้ค่านั้น ถ้าไม่มีใช้ลิสต์ว่าง ซึ่งเมื่อ DEBUG เป็น True Django ยอมรับ localhost และ 127.0.0.1 ให้เอง

ส่วนที่สามคือ DATABASES แทนที่ค่าเดิมในบทที่ 7

ENGINE ยังเป็นค่าคงที่ที่เขียนในไฟล์ ส่วนข้อมูลเชื่อมต่ออ่านจาก .env โดยพารามิเตอร์ตัวที่สอง '' คือค่าที่ใช้เมื่อไม่มีตัวแปรนั้น

ขั้นตอนที่ 7 เปิดเซิร์ฟเวอร์และทดสอบ

ผลลัพธ์ที่ควรได้

  • เว็บทุกหน้าทำงานเหมือนบทที่ 13 และเชื่อมต่อฐานข้อมูลได้ แม้ค่าทั้งหมดมาจากไฟล์ .env ไม่ใช่ settings.py
  • ใน settings.py ไม่มีรหัสผ่านฐานข้อมูลและรหัสลับของ Django อยู่ในไฟล์
  • ทดลองเปลี่ยน DEBUG=False ใน .env โดยไม่มี PRODUCTION_HOST เซิร์ฟเวอร์จะไม่เริ่มทำงานและแสดง CommandError: You must set settings.ALLOWED_HOSTS if DEBUG is False. หากเพิ่ม PRODUCTION_HOST=127.0.0.1 เซิร์ฟเวอร์เริ่มได้ แต่สแตติกไฟล์ เช่น /static/app_general/main.css จะไม่ถูกส่ง (ตอบ 404) เพราะ runserver ส่งสแตติกไฟล์เฉพาะเมื่อ DEBUG เป็น True ซึ่งบทที่ 15 แก้ปัญหานี้ ทดลองเสร็จให้เปลี่ยนค่ากลับเป็น DEBUG=True และลบบรรทัด PRODUCTION_HOST
