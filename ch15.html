การนำขึ้นใช้งานจริง (Deploy)

อ้างอิง GitHub: บรานช์ 15-deploy-heroku · ส่วนที่เปลี่ยนจากบทก่อนหน้า

วัตถุประสงค์

เมื่อจบบทนี้ ผู้เรียนเตรียมโปรเจกต์สำหรับการนำขึ้นใช้งานจริง (Deploy) และนำเว็บ จันทร์ไรเดอร์ ขึ้นให้ผู้อื่นเปิดผ่านอินเทอร์เน็ตได้บนบริการ Render โดยใช้ฐานข้อมูล PostgreSQL ของ Render

ขั้นตอนที่ 1 ทำความเข้าใจการนำขึ้นใช้งานจริง

  • เซิร์ฟเวอร์ runserver ใช้เฉพาะตอนพัฒนา ตามเอกสารของ Django ไม่ควรใช้กับเว็บจริง เว็บจริงใช้เว็บเซิร์ฟเวอร์ที่รองรับมาตรฐาน WSGI ซึ่งเป็นมาตรฐานที่เว็บเซิร์ฟเวอร์ใช้เรียกโปรเจกต์ผ่านไฟล์ wsgi.py (ที่เห็นในบทที่ 1) ในที่นี้ใช้ gunicorn ซึ่งทำงานบนระบบ Unix เช่น Linux ของ Render
  • เมื่อ DEBUG เป็น False (บทที่ 14) Django ไม่ส่งสแตติกไฟล์ให้ ต้องใช้ WhiteNoise ซึ่งเป็นแพ็กเกจที่ทำให้แอป Django ส่งสแตติกไฟล์เองได้
  • คำสั่ง collectstatic ของ Django รวมสแตติกไฟล์จากทุกแอป (รวมถึงของหน้าผู้ดูแลระบบ) ไปไว้ในโฟลเดอร์เดียวตาม STATIC_ROOT เพื่อให้เว็บเซิร์ฟเวอร์ส่งไฟล์ได้
  • ฐานข้อมูลบน Render ใช้ PostgreSQL จึงตรงกับฐานข้อมูลที่ใช้ตั้งแต่บทที่ 7 และโค้ดใน settings.py ที่อ่านค่าจาก .env ในบทที่ 14 ใช้ได้โดยไม่ต้องแก้ โดยเปลี่ยนเฉพาะค่าตัวแปรบนเซิร์ฟเวอร์

ขั้นตอนที่ 2 ติดตั้ง gunicorn และ WhiteNoise

ขั้นตอนที่ 3 แก้ settings.py

เปิดไฟล์ project_jrd/settings.py แล้วแก้ 3 จุด จุดแรก เพิ่ม WhiteNoise ใน MIDDLEWARE ต่อจากบรรทัด SecurityMiddleware

จุดที่สอง เพิ่มค่า 2 บรรทัดต่อจาก STATIC_URL = 'static/'

โค้ด / คำสั่งคำอธิบาย
'whitenoise.middleware.WhiteNoiseMiddleware'มิดเดิลแวร์ (Middleware) คือส่วนที่คำขอและการตอบกลับทุกครั้งผ่านก่อนถึงวิว WhiteNoise ต้องอยู่ต่อจาก SecurityMiddleware เพื่อรับคำขอสแตติกไฟล์และตอบกลับเอง
STATIC_ROOT = BASE_DIR / 'staticfiles'โฟลเดอร์ปลายทางของ collectstatic คือ staticfiles ในโฟลเดอร์โปรเจกต์ ใช้ชื่อต่างจากโฟลเดอร์ static ของแต่ละแอปเพื่อไม่ให้สับสน
STATICFILES_STORAGE = '...CompressedManifestStaticFilesStorage'ตัวจัดเก็บสแตติกไฟล์ของ WhiteNoise ที่บีบอัดไฟล์ และเติมรหัสสั้น ต่อท้ายชื่อไฟล์ตามเนื้อหา เช่น main.9bcd2241ce49.css เมื่อเนื้อหาไฟล์เปลี่ยน ชื่อไฟล์ก็เปลี่ยน เบราว์เซอร์จึงไม่ใช้ไฟล์เก่าที่เก็บไว้

จุดที่สาม เพิ่มค่า CSRF_TRUSTED_ORIGINS ต่อจากบรรทัด ALLOWED_HOSTS ที่เพิ่มในบทที่ 14

ตั้งแต่ Django 4.0 การตรวจโทเคน CSRF ของคำขอ POST (บทที่ 10) เทียบหัวข้อ Origin ของคำขอกับโปรโตคอลและโฮสต์ที่ Django เห็น ถ้าเซิร์ฟเวอร์รับคำขอผ่านตัวกลางที่แปลง HTTPS เป็น HTTP ค่าจะไม่ตรงกันและ Django ปฏิเสธคำขอ POST ด้วยสถานะ 403 CSRF_TRUSTED_ORIGINS คือรายการต้นทางที่เชื่อถือ ซึ่งต้องมีโปรโตคอล (https://) นำหน้า บรรทัดนี้เพิ่มโดเมนของเว็บจริงเข้าไป ส่วนบนเครื่องของผู้เรียนที่ไม่มี PRODUCTION_HOST ค่าเป็นลิสต์ว่างและไม่มีผล

ขั้นตอนที่ 4 สร้างไฟล์ requirements.txt

Render ติดตั้งแพ็กเกจจากไฟล์ requirements.txt ซึ่งเป็นรายการแพ็กเกจและเวอร์ชันที่ pip อ่านได้ สร้างจากข้อมูลใน Pipfile.lock ด้วยคำสั่ง

โค้ด / คำสั่งคำอธิบาย
pipenv requirementsคำสั่งของ pipenv ที่แสดงรายการแพ็กเกจและเวอร์ชันที่ล็อกไว้ในรูปแบบของ requirements.txt
> requirements.txtเครื่องหมาย > เขียนผลลัพธ์ของคำสั่งลงไฟล์ requirements.txt แทนการแสดงบนจอ

เปิดไฟล์ requirements.txt ที่ได้ ต้องมีบรรทัดของ django (เวอร์ชัน 4.0.x), gunicorn, whitenoise, psycopg2-binary และ python-dotenv ซึ่งแต่ละบรรทัดอยู่ในรูป ชื่อแพ็กเกจ==เวอร์ชัน อาจมีเงื่อนไขต่อท้าย เช่น ; python_version >= '3.8' และมีแพ็กเกจที่ Django เรียกใช้ต่อ เช่น asgiref และ sqlparse รวมอยู่ด้วย

ทุกครั้งที่ติดตั้งหรือเปลี่ยนแพ็กเกจด้วย pipenv ให้สร้างไฟล์นี้ใหม่

ขั้นตอนที่ 5 สร้างไฟล์ build.sh

Render รันคำสั่งในช่อง Build Command ทุกครั้งที่นำโค้ดใหม่ขึ้นเว็บ สร้างไฟล์ build.sh ในโฟลเดอร์โปรเจกต์ (ข้าง manage.py)

โค้ด / คำสั่งคำอธิบาย
#!/usr/bin/env bashบรรทัดแรกบอกว่าไฟล์นี้ใช้โปรแกรม bash (เชลล์ของ Linux) รัน
set -o errexitให้สคริปต์หยุดทันทีถ้าคำสั่งใดล้มเหลว
pip install -r requirements.txtติดตั้งแพ็กเกจทั้งหมดในไฟล์ requirements.txt
python manage.py collectstatic --no-inputรวมสแตติกไฟล์ไปไว้ที่ STATIC_ROOT --no-input คือไม่ต้องถามยืนยัน
python manage.py migrateสร้างหรือปรับตารางในฐานข้อมูลบน Render ตามไมเกรชัน (บทที่ 7)

ไฟล์นี้ทำงานบน Linux ของ Render จึงต้องบันทึกแบบขึ้นบรรทัดใหม่ของ Linux (LF) ใน Visual Studio Code ดูได้ที่แถบสถานะมุมขวาล่าง ถ้าแสดง CRLF ให้คลิกแล้วเลือก LF ก่อนบันทึก หากไฟล์บน GitHub เป็น CRLF ขั้นตอน Build บน Render อาจล้มเหลว

ขั้นตอนที่ 6 กำหนดเวอร์ชัน Python บน Render

Render เลือกเวอร์ชัน Python ให้เองถ้าไม่กำหนด ซึ่งบริการที่สร้างใหม่ใช้ Python 3.14 ขณะที่ Django 4.0 รองรับ Python 3.8 ถึง 3.10 จึงต้องกำหนดเวอร์ชันเอง โดยสร้างไฟล์ .python-version ในโฟลเดอร์โปรเจกต์ (ข้าง manage.py) เขียนเวอร์ชันบรรทัดเดียว หากไม่ระบุเลขท้าย Render ใช้รุ่นล่าสุดของเวอร์ชันนั้น

ขั้นตอนที่ 7 ทดสอบจำลองการใช้งานจริงบนเครื่อง

ก่อนอัปโหลด ทดสอบว่า WhiteNoise ส่งสแตติกไฟล์ได้เมื่อ DEBUG เป็น False แก้ไฟล์ project_jrd/.env ชั่วคราว โดยเปลี่ยน DEBUG=True เป็น DEBUG=False และเพิ่มบรรทัด PRODUCTION_HOST=127.0.0.1 แล้วรันคำสั่ง

คำสั่ง collectstatic แสดงจำนวนไฟล์ที่คัดลอก (เช่น 152 static files copied ... 418 post-processed) และสร้างโฟลเดอร์ staticfiles เปิด http://127.0.0.1:8000/ ต้องเห็นหน้าเว็บที่มี CSS ภาพ และฟอนต์ครบเหมือนบทที่ 13 (ซึ่งต่างจากการทดลองท้ายบทที่ 14 ที่สแตติกไฟล์หาย) แล้วหยุดเซิร์ฟเวอร์และแก้ .env กลับเป็น DEBUG=True พร้อมลบบรรทัด PRODUCTION_HOST

บน Windows ให้ทดสอบด้วย runserver เพราะ gunicorn ทำงานบน Windows ไม่ได้ gunicorn จะทำงานบนเซิร์ฟเวอร์ของ Render

ขั้นตอนที่ 1 ถึง 7 ทำในโปรเจกต์บนเครื่องของผู้เรียน ส่วนขั้นตอนที่ 8 ถึง 11 ทำบนเว็บไซต์ GitHub และ Render โดยต้องมีบัญชีของทั้งสองเว็บไซต์

ขั้นตอนที่ 8 อัปโหลดโค้ดขึ้น GitHub

Render นำโค้ดจากรีโพสิตอรี (Repository) บน GitHub ไปสร้างเว็บ ติดตั้งโปรแกรม Git จาก https://git-scm.com (ถ้ายังไม่มี) สร้างบัญชีที่ https://github.com และสร้างรีโพสิตอรีใหม่ที่ https://github.com/new (ตั้งชื่อ เช่น django-junraider ไม่ต้องเลือกให้สร้างไฟล์ README) จากนั้นเพิ่มบรรทัดนี้ท้ายไฟล์ .gitignore ที่สร้างในบทที่ 14 เพื่อไม่ให้อัปโหลดโฟลเดอร์ที่ collectstatic สร้าง

ถ้าใช้ Git เป็นครั้งแรกบนเครื่องนี้ ให้ตั้งชื่อและอีเมลที่จะบันทึกในประวัติของ Git ก่อน (ทำครั้งเดียวต่อเครื่อง)

จากนั้นรันคำสั่งต่อไปนี้ในโฟลเดอร์โปรเจกต์ โดยแทน <ชื่อบัญชี> ด้วยชื่อบัญชี GitHub ของตน ครั้งแรกที่ git push จะมีหน้าต่างให้เข้าสู่ระบบ GitHub

โค้ด / คำสั่งคำอธิบาย
git initสร้างรีโพสิตอรีของ Git ในโฟลเดอร์นี้ (ข้ามขั้นนี้ถ้าโฟลเดอร์เป็นรีโพสิตอรีอยู่แล้ว)
git add .เลือกไฟล์ทั้งหมดที่ .gitignore ไม่ได้ยกเว้นเพื่อเตรียมบันทึก
git update-index --chmod=+x build.shตั้งสิทธิ์ให้ไฟล์ build.sh รันได้ (Executable) เพราะ Render เรียกไฟล์นี้เป็นโปรแกรม Windows ไม่มีสิทธิ์ประเภทนี้ในไฟล์ จึงต้องตั้งใน Git
git commit -m "..."บันทึกการเปลี่ยนแปลงพร้อมข้อความอธิบาย
git branch -M mainตั้งชื่อบรานช์หลักเป็น main
git remote add origin <URL>ผูกรีโพสิตอรีในเครื่องกับรีโพสิตอรีบน GitHub
git push -u origin mainส่งโค้ดขึ้น GitHub

เมื่อสำเร็จ เปิดหน้ารีโพสิตอรีบน GitHub แล้วต้องเห็นไฟล์ build.sh, requirements.txt, .python-version และไม่เห็นไฟล์ project_jrd/.env

ขั้นตอนที่ 9 สร้างฐานข้อมูล PostgreSQL บน Render

  • สมัครและเข้าสู่ระบบที่ https://dashboard.render.com แล้วเชื่อมบัญชี GitHub ตามที่ Render แนะนำ
  • คลิก New (+) แล้วเลือก Postgres
  • ตั้ง Name (เช่น django-junraider-db) เลือก Region ให้เป็นที่เดียวกับที่จะใช้กับเว็บในขั้นตอนถัดไป และเลือกแผน (Compute Plan) ฐานข้อมูลแผน Free ของ Render หมดอายุ 30 วันหลังสร้าง
  • คลิก Create Database รอจนสถานะเป็น Available
  • คลิกเมนู Connect มุมขวาบนของหน้าฐานข้อมูล แล้วคัดลอก Internal URL (ใช้ได้กับเว็บของ Render ในภูมิภาคเดียวกัน)

Internal URL มีรูปแบบ postgresql://ผู้ใช้:รหัสผ่าน@โฮสต์/ชื่อฐานข้อมูล แยกเป็นค่าที่ใช้ในขั้นตอนถัดไปได้ 4 ค่า ได้แก่ ผู้ใช้ รหัสผ่าน โฮสต์ และชื่อฐานข้อมูล ส่วนพอร์ตคือ 5432

ขั้นตอนที่ 10 สร้างเว็บเซอร์วิสบน Render

  • ใน Render คลิก New (+) แล้วเลือก Web Service เลือกรีโพสิตอรี django-junraider ที่เพิ่งอัปโหลด (ให้สิทธิ์ Render เข้าถึงรีโพสิตอรีถ้าถูกถาม)
  • ตั้ง Name เช่น django-junraider ซึ่งมักเป็นส่วนแรกของที่อยู่เว็บ (ชื่อ.onrender.com) เลือก Language เป็น Python 3 และ Region เดียวกับฐานข้อมูล
  • ช่อง Build Command ใส่ ./build.sh
  • ช่อง Start Command ใส่ gunicorn project_jrd.wsgi
  • เลือกแผนตามต้องการ แล้วเปิดส่วน Advanced เพื่อเพิ่มตัวแปรสภาพแวดล้อม (Environment Variable) ตามตารางด้านล่าง

  • เมื่อ Logs แสดงว่าเว็บทำงานแล้ว (Live) ให้เปิดที่อยู่ที่ Render แสดงใต้ชื่อเซอร์วิส
  • ถ้าโดเมนจริงไม่ตรงกับค่า PRODUCTION_HOST ให้แก้ค่าในแท็บ Environment แล้วบันทึก Render จะนำขึ้นใหม่อัตโนมัติ

ขั้นตอนที่ 11 สร้างบัญชีผู้ดูแลและเพิ่มข้อมูลเมนูบนเว็บจริง

ฐานข้อมูลบน Render เป็นฐานข้อมูลใหม่ที่มีเฉพาะตารางจากไมเกรชัน ยังไม่มีบัญชีผู้ดูแลและข้อมูลเมนู เว็บเซอร์วิสแผน Free ของ Render ไม่มีหน้าต่าง Shell ให้รันคำสั่ง จึงสร้างบัญชีผู้ดูแลจากเครื่องของผู้เรียน โดยให้โปรเจกต์ในเครื่องเชื่อมต่อกับฐานข้อมูลบน Render ชั่วคราว

  • ในหน้าฐานข้อมูลบน Render คลิกเมนู Connect แล้วคัดลอก External URL ซึ่งเป็นที่อยู่สำหรับเชื่อมต่อจากเครื่องที่อยู่นอก Render รูปแบบเหมือน Internal URL แต่โฮสต์ยาวกว่า
  • เปิดไฟล์ project_jrd/.env ในเครื่อง แล้วเปลี่ยนค่า DB_NAME, DB_USER, DB_PASS, DB_HOST ชั่วคราวเป็นค่าจาก External URL (คงค่า DB_PORT=5432)

รันคำสั่งสร้างบัญชีผู้ดูแล แล้วตอบคำถามเหมือนบทที่ 11 บัญชีจะถูกบันทึกลงฐานข้อมูลบน Render

เมื่อสร้างเสร็จ ให้แก้ไฟล์ .env กลับเป็นค่าของฐานข้อมูลในเครื่องตามบทที่ 14 จากนั้นเปิด https://<โดเมนของเว็บ>/admin/ เข้าสู่ระบบด้วยบัญชีที่สร้าง แล้วเพิ่มเมนูด้วยปุ่ม เพิ่ม food กรอกข้อมูลตามตัวอย่างในบทที่ 8 และช่อง Image relative url ตามตารางในบทที่ 12 เช่น app_foods/food-red-spicy.jpg ไฟล์ภาพอยู่ในโค้ดที่อัปโหลดแล้ว

ผลลัพธ์ที่ควรได้

  • Logs ของขั้นตอน Build แสดงการติดตั้งแพ็กเกจ collectstatic และ Applying ... ของ migrate ไม่มีข้อผิดพลาด
  • เปิดที่อยู่ https://<โดเมนของเว็บ>/ เห็นหน้าแรกพร้อมฟอนต์ ภาพ และสีเหมือนบทที่ 13
  • หน้า /foods/ แสดงเมนูที่เพิ่มในขั้นตอนที่ 11 พร้อมภาพ
  • หน้า /subscription ส่งฟอร์มแล้วไปหน้าขอบคุณ ไม่แสดงข้อความ 403 และแถวใหม่ปรากฏในตาราง Subscription ในหน้าผู้ดูแลระบบ
  • เข้า /admin/ ได้ และหน้าผู้ดูแลระบบมี CSS ครบ (ซึ่งเป็นผลของ WhiteNoise กับ collectstatic)
